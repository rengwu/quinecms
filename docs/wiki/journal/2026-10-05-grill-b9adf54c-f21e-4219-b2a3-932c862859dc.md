## Question 40

```text
Round: lean-sitebuilder — editor and saving
Question: Which UI approach should the React editor use?
Context: This affects dialogs, menus, field controls, and the drawer. Base UI provides unstyled React primitives; a styled kit provides more ready-made design. The native-only rule remains specific to the throwaway grill-form.
Recommendation: Use Base UI for complex controls, native elements where sufficient, and CSS Modules for a small custom design. Import only what the editor uses.
Options: Base UI plus CSS Modules / A styled shadcn/ui setup with Tailwind / Native controls and custom React components only
```

## Question 41

```text
Round: lean-sitebuilder — editor and saving
Question: How should block authors scope their CSS?
Context: The editor and preview share a document. Global resets or selectors such as button { ... } could change other blocks or the editor. Scoped CSS still lets each block have its own design.
Recommendation: Require CSS Modules or the framework's scoped styles. Keep shared resets/theme variables in the site shell and avoid block-owned global rules.
Options: CSS Modules or framework-scoped styles / Author-managed block namespaces, checked during the build
Selected: CSS Modules or framework-scoped styles
Notes: 
```

## Question 42

```text
Round: lean-sitebuilder — editor and saving
Question: What should the main Save button commit?
Context: An editor might change a page, site navigation, and a collection definition before saving. Related file changes can be committed together to the draft branch.
Recommendation: Save all pending editor changes as one commit, with a clear unsaved-changes indicator. This avoids accidentally leaving part of a site change behind.
Options: All pending editor changes in one draft commit / Only the current page or record and its required related changes
Selected: All pending editor changes in one draft commit
Notes: 
```

## Question 43

```text
Round: lean-sitebuilder — editor and saving
Question: How should unsaved content survive an accidental reload?
Context: This is recovery of text/content edits, separate from Git Save. Binary uploads are not included. Persistent recovery would leave a copy of draft content on that device after the tab closes.
Recommendation: Restore unsaved edits within the tab session. It matches the chosen GitHub-token session model without retaining draft content indefinitely.
Options: Recover edits within the tab session, including reloads / Keep a local recovery copy across browser restarts / Keep edits in memory only; reloading loses unsaved work
Selected: Recover edits within the tab session, including reloads
Notes: 
```

## Question 44

```text
Round: lean-sitebuilder — editor and saving
Question: How should users edit the Markdown stored inside text blocks?
Context: The storage format is already Markdown. A visual editor hides its syntax, while a textarea exposes markup but is simpler to implement and extend. Both can update the page preview live.
Recommendation: Use a visual editor limited to headings, paragraphs, emphasis, links, and lists, saving Markdown. This suits nontechnical editors while keeping the feature set small.
Options: Visual formatting controls that save Markdown / Markdown textarea with a small formatting toolbar / Both visual and source modes
Selected: Visual formatting controls that save Markdown
Notes: 
```

```text
Context: Switching a block version may leave new required fields empty, as you requested. Structurally invalid files still need protection; this question concerns ordinary incomplete content.
```
