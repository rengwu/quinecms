## Question 1

```text
Round: lean-sitebuilder
Question: What does ‘all while being a static website’ permit?
Context: Both the public site and editor can be static. Git writes still need authorization, and redeployment needs a build runner. GitHub’s standard web OAuth token exchange requires a client secret, which cannot safely live in the static bundle.
Recommendation: A small on-demand auth/Git helper plus build jobs avoids an always-running CMS and supports a smoother login.
Options: Allow a small serverless auth/Git helper plus build jobs / No custom server-side code; accept a user-supplied Git token or compatible external auth service, plus build jobs
Selected: Something else
Notes: allow user access to the admin portal via a environmentvariable-set credential. then when "submitting",  a user-supplied git token is required. just github compatibility is fine for now
```

## Question 4

```text
Round: lean-sitebuilder
Question: Can block authors be required to follow a shared dependency contract?
Context: React, Svelte, Vue, and vanilla blocks can coexist. Loading one shared runtime per framework requires compatible versions and declared dependencies; arbitrary self-bundled blocks cannot guarantee deduplication.
Recommendation: Require declared dependencies and compatible shared versions so blocks can share libraries reliably.
Options: Require declared dependencies and compatible shared versions / Accept arbitrary bundles, even when libraries must be duplicated / Support only one interactive framework initially
Selected: Require declared dependencies and compatible shared versions
Notes: 
```

## Question 5

```text

Context: All options include the side drawer and live preview. The difference is what can be rearranged and styled.
```

## Question 6

```text
Round: lean-sitebuilder
Question: Should Save publish after a rebuild, or should saving and publishing be separate?
Context: Unsaved edits appear in the live preview first. This determines when they reach Git and become public.
Recommendation: Explicit Save → Git commit → automatic rebuild matches your original description.
Options: Explicit Save commits and automatically redeploys / Save creates a draft; Publish separately triggers deployment / Autosave changes to Git and continuously redeploy
Selected: Something else
Notes: save produces commits, which are pushed to a branch with draft "unpublished" content. when another "publish" action is clicked, whatever is in the unpublished draft is merged to main branch, and then deployed
```
