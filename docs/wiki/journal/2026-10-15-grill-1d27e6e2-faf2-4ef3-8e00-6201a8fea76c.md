## Question 1

```text
Round: Tessera — reusable content and unfinished reference links
Question: Should Tessera’s listings use shared collection records, with a small reusable engine extension?
Description (Markdown source):
The reference has 59 reachable pages. The starter now models docs, API endpoints, blog posts, customer stories and releases as collections. The engine currently exposes only six hardcoded fields from one collection to a listing block. That cannot supply Tessera’s categories, author details, release bodies, or the homepage’s combined blog/release section. A regression test exposes the limitation.

This choice affects future themes too: one shared article should update both its detail page and every listing.
Recommendation: Extend the engine with explicit collection/field selection for reusable blocks. Keep Tessera’s rendering in the library and its records in the site. Preserve existing block behavior and avoid sending unrelated collection data to public blocks.
Options: Extend the engine; keep content shared (recommended) / Keep the engine unchanged; use separate editable lists with duplicated content
Selected: (notes only)
Notes: before we extend, i want to know exactly what will we extend and introduce. elaborate in detail
```
