## Question 62

```text
Round: Block library
Question: How should editors manage repeated items inside a block?
Description (Markdown source):
Features, team members, testimonials, logo lists, FAQ items and footer links need groups of editable fields. The old system uses variable-length lists; our current editor does not yet have a standard list field.
Recommendation: Add a reusable list editor with Add, Remove and drag-to-reorder, so these blocks can have the number of items the content needs.
Options: Editable lists: add, remove and reorder items / Fixed item slots for each layout
Selected: Editable lists: add, remove and reorder items
Notes: 
```

## Question 63

```text
Round: Block library
Question: Where should Blog blocks get their article cards?
Description (Markdown source):
The old Blog blocks store their own title, image, excerpt, date and link for each card. Our current CMS already has schema-based collections and entry routes, but collection-list blocks only expose titles and links.
Recommendation: Select a collection and map its fields to the card's title, image, excerpt and date. Use the existing entry routes for article links, avoiding duplicate article content.
Options: Use collection entries with field mapping / Manually author the cards inside each block / Support both collection entries and manual cards
Selected: Use collection entries with field mapping
Notes: 
```

## Question 64

```text
Round: Block library
Question: How should Contact and Newsletter forms submit?
Description (Markdown source):
The site is static. Several old form layouts have no submission destination, so copying their appearance would leave a nonfunctional form.
Recommendation: Allow an editor-configured external form endpoint. Require it before publishing a form; the service handles delivery and its response. No new backend is needed in the builder.
Options: Submit to a configured external form endpoint / Use a button linking to an external contact or signup page / Defer blocks that contain submission forms
Selected: Submit to a configured external form endpoint
Notes: 
```

## Question 65

```text
Round: Block library
Question: Where should the imported Footer layouts be used?
Description (Markdown source):
Public pages already have a built-in footer. Adding another footer as an ordinary block would otherwise display both.
Recommendation: Treat Footer layouts as page blocks for this import and omit the built-in footer on pages using one. A shared footer editor can be a separate feature.
Options: Page blocks that replace that page's built-in footer / A shared site-wide footer configured once / Defer Footer blocks for now
Selected: A shared site-wide footer configured once
```
