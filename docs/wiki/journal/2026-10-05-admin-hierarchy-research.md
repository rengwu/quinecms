# Admin hierarchy research

The user requested research on Add block alignment/list ambiguity and separation of collection schema editing from entry authoring. Inspected the existing UI source and official Carbon, NN/g, Sanity, Payload and Strapi documentation.

The [proposal](../discussions/admin-hierarchy-proposal.md) recommends moving Add block into the Blocks header, opening collections on an entry list, and providing an explicit separate schema screen. It also compares a top-level Content/Collection schemas split and per-collection Entries/Schema tabs. Source observations, user requirements and unaccepted design recommendations are distinguished.

Application code and accepted saving/schema contracts remain unchanged. The pending choice is navigation alternative A/B/C and button placement. No product verification was needed for this documentation-only research; wiki structure and links were checked.
