## Question 22

```text
Round: i18n UI presentation choices
Question: Where should shared fields (Size, Featured ingredient, image selection) appear while editing a secondary language?
Description (Markdown source):
Shared fields hold one value for every language (DEC-203). Editing one while Indonesian is selected changes English too.

- Prototype A keeps them in schema order with a **Shared** badge, editable.
- Prototypes B and C group them after the translated fields under **Shared by all languages**, still editable.

The interleaved layout makes an accidental shared edit easier; grouping changes field order relative to the schema.
Recommendation: Group them under “Shared by all languages”, still editable. It separates translation work from shared data without forcing a language switch for small fixes.
Options: Group them under “Shared by all languages”, still editable / Keep schema order with a Shared badge, editable / Group them read-only; change them in the main language / Hide them while editing a secondary language
Selected: Keep schema order with a Shared badge, editable
Notes: keep it simple man, don't move them around
```

## Question 24

```text
Round: i18n UI presentation choices
Question: What should the live preview show by default when a secondary language is selected?
Description (Markdown source):
Two preview modes were prototyped:

- **Draft:** the current unsaved Indonesian copy; blank values are marked as missing, never filled from English. A note says what visitors would currently get.
- **Visitor:** what a visitor receives after Publish under the current policy: the copy if eligible, otherwise the whole English item (or a strict-policy block).

Other items on the page (layout, template, referenced products) always resolve as a visitor would receive them, with dashed outlines when shown in another language.
Recommendation: Draft by default with a Visitor toggle. It matches today's live preview of unsaved edits while answering “what will people see?” in one click.
Options: Draft by default, with a Visitor toggle / Visitor by default, with a Draft toggle / Draft only; describe the visitor result in text
Selected: Draft by default, with a Visitor toggle
```

## Question 26

```text
Round: i18n UI presentation choices
Question: How should media alternative text be localized?
Description (Markdown source):
A media field stores the chosen image and its alt text together. With only shared/per-language settings:

- **Shared:** Indonesian visitors get English alt text.
- **Per language:** translators must re-select the same image in every language to translate its alt text.

The prototype adds a third setting, “Shared image, separate alt text per language” (Schemas → Collections → Products → Photo), and shows image and alt text as separate rows with their own Shared/Indonesian badges.
Recommendation: Offer three settings for media fields: shared; shared image with per-language alt text; per-language image and alt text. It keeps alt text accessible without duplicating image choices.
Options: Three settings: shared; shared image with per-language alt; per-language image and alt / Alt text is always per language when i18n is on; the image follows the field setting / Two settings only: the image and alt text are shared or per language together
```

```text
Question: What should happen when a schema or structure change makes eligible language copies incomplete?
Description (Markdown source):
Automatic eligibility (DEC-200) means some edits silently switch visitors back to English:

- Making the required Size field per-language demoted both eligible product copies in the prototype.
- Adding an English list row whose Name is required makes the Indonesian copy incomplete until that row is translated.

The prototype allows the change and shows an “Effect on existing content” box listing affected copies; the New item form notes the effect on other languages.

Try: http://localhost:5317/?p=a&scope=item&s=schema
```

## Question 28

```text
Round: i18n UI presentation choices
Question: How should an editor start a new language copy of an item?
Description (Markdown source):
The prototype follows the creation convention (DEC-129): **Add Indonesian copy** opens a **New Indonesian copy** form with blank translated fields, Cancel and Create. The preview shows the pending values; Cancel leaves nothing behind.

Prefilling with English text would make the copy eligible immediately (DEC-200) and publish English under /id/ as if it were Indonesian. Typing into an empty language without a form would create copies as a side effect of exploration.
Recommendation: Explicit New copy form with blank translated fields. It matches existing Create/Cancel behavior and cannot make untranslated text eligible by accident.
Options: Explicit form, blank translated fields, Create/Cancel / Explicit form prefilled with main-language text / No form: typing into an empty language starts the copy
```
