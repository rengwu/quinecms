## Question 69

```text
Round: Site Layout — round one
Question: Should content max-width and page gutter stay outside individual layouts?
Description (Markdown source):
You suggested keeping these two shared controls. Today they supply advisory values, so blocks can choose whether to use them. Keeping them shared would also let the values survive layout switches. Moving them into each layout would let its author choose whether and how to expose them.
Recommendation: Keep both as shared, optional values. This preserves useful site-wide controls without forcing a width or gutter on any layout or block.
Options: Keep both as shared, optional values / Let each layout own them
Selected: Keep both as shared, optional values

```

## Question 71

```text
Round: Site Layout — round one
Question: Should editing layout settings show a live website preview?
Description (Markdown source):
The existing rule limits live website previews to page editing. A Site Layout preview could show a chosen page's blocks inside the layout as settings change, with desktop and mobile widths. The alternative is a normal settings page, with preview available by returning to Pages.
Recommendation: Show a live preview alongside layout settings, using a page selector. Layout changes affect the whole surrounding design and benefit from immediate feedback.
Options: Yes, preview alongside layout settings / No, keep previews in Pages
Selected: Yes, preview alongside layout settings
Notes: 
```

## Question 72

```text
Round: Site Layout — round one
Question: What should clicking a layout card do?
Description (Markdown source):
The block picker currently applies a card directly and provides a separate Preview action. For layouts, applying a different layout replaces the active settings with that layout's defaults, as agreed. Preview alone would leave the current layout/settings intact. Applying changes the local draft; the existing Save draft and Publish workflow still controls persistence and going live.
Recommendation: Match the block picker: apply directly from the card, and keep a separate Preview action for inspection.
Options: Apply from the card; separate Preview action / Open preview first; then choose Use layout
Selected: Apply from the card; separate Preview action
Notes: 
```

## Question 73

```text
Round: Site Layout — round one
Question: How should new layout implementations be installed?
Description (Markdown source):
Blocks are currently installed by a developer in the project's source and made available through a rebuild. Editors then choose installed blocks in the picker. Layouts could follow the same model, or the admin could gain a package-import workflow.
Recommendation: Use developer installation and a rebuild, matching blocks. Authors retain control over layout code and settings; editors choose among the installed layouts.
Options: Developer installs in source and rebuilds / Editor imports layout packages in the admin
Selected: Developer installs in source and rebuilds
Notes: 
```
