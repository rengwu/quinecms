## Question 82

```text
Round: Collections & schemas · who owns the blueprint?
Question: Should each collection own its schema, or should several collections be able to share one schema?
Description (Markdown source):
A **schema** defines fields and rules. A **collection** groups entries. An **entry** holds actual values. A **generic page** controls presentation.

Our current builder stores the fields directly on each collection. Your accepted reusable object definitions can work with either model:

**Collection-owned schema:** Blog and News each define their own fields. Both can reuse an SEO object definition. Their whole schemas can evolve independently, although duplicated structures may drift.

**Independent reusable schema:** Blog and News both select the same Article schema. Editing Article's fields affects both collections. This keeps complete structures consistent, but adds a schema library and requires checking the impact across its uses.

In either case, Blog and News keep separate entries, URL prefixes and template assignments. Sharing structure does not share values. A relation still targets one collection, as you already chose.
Recommendation: Keep each collection's whole schema attached to that collection for now, using named object definitions for shared field groups. Choose independent whole schemas if separate collections need their entire structures kept identical.
Options: Each collection owns its schema; reuse object definitions / Independent schemas can be shared by multiple collections
Selected: Each collection owns its schema; reuse object definitions
```
