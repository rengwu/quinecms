## Question 94

```text
Round: Content model · reusable definitions within three levels
Question: Should reusable object definitions be allowed to contain themselves?
Description (Markdown source):
You have accepted up to three owned object/list levels. Ordinary nesting is now agreed: a Product can own specification groups that own specification rows. This follow-up concerns a definition that repeats itself.

For example, a reusable Menu item could contain label, link and a children list whose rows use Menu item again. This is a recursive definition. Indirect recursion, such as A containing B and B containing A, raises the same issue.

Allowing recursion lets one definition describe each level of a tree. Actual content would still stop at three owned levels, so defaults, required-field rules and editing controls would need to handle the stopping point. A recursive schema can have finite content; it does not inherently mean an infinite document.

Rejecting recursion still permits nested objects/lists and reuse of the same definition in several independent places. It requires a definition chain to end, such as Menu group containing Menu link rows. Similar fields may need separate definitions for different levels.

This choice concerns owned object definitions only. It does not decide whether independent entries can reference one another in a cycle; reference resolution remains a separate engineering concern.
Recommendation: Reject direct and indirect recursive object definitions for this increment. Keep ordinary nested reuse within the three-level cap, avoiding depth-dependent field and default behavior. This is an additional simplicity choice, not a consequence already implied by your depth answer.
Options: Reject recursive definitions; allow ordinary nested reuse / Allow recursive definitions within the three-level content limit
Selected: Reject recursive definitions; allow ordinary nested reuse
```
