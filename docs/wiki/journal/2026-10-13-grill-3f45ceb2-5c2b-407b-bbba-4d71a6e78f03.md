## Question 6

```text
Round: Engine separation — library ownership and remaining boundaries
Question: What should be the supported boundary for site customization?
Description (Markdown source):
You are leaning toward extensions only. Site-owned blocks, layouts, styles, interactions and their settings controls would use engine-provided interfaces. Replacing core editor, persistence or build files would create per-site engine patches to maintain.
Recommendation: Support extensions only. When a design needs a missing capability, extend the shared engine interface instead of replacing core files inside that site.
Options: Extensions only; core changes belong in the shared engine / Also support site-specific replacements of core files
Selected: Extensions only; core changes belong in the shared engine
Notes: if a specific core capability is needed, it needs to be added at the core repository
```

## Question 7

```text
Round: Engine separation — library ownership and remaining boundaries
Question: Should a library subscription supply implementations directly, or copy them into the site repository?
Description (Markdown source):
Direct consumption keeps shared implementations outside the site's committed files; the build obtains them from the library. Copying makes those implementations site-owned immediately, and future library changes must be brought over manually. Either approach can populate the same admin catalogs, with subscriptions configured outside the portal.
Recommendation: Consume library implementations directly by default. This keeps the site repo small and preserves a clear source for shared updates. How a site customizes that code is the next decision.
Options: Use library implementations as dependencies / Copy library implementations into each site
Selected: Use library implementations as dependencies
Notes: 
```

## Question 8

```text
Round: Engine separation — library ownership and remaining boundaries
Question: May an older editor save a draft after its engine or editable block/layout code has changed?
Description (Markdown source):
For example, a developer upgrades the draft while a client's open browser still uses the previous editor. Today's checks can allow draft saves using the old definitions, although publication is blocked. This question was unanswered in the discarded form. Manual migration remains the site maintainer's responsibility either way.
Recommendation: Require a matching editor before saving or publishing, and preserve unsaved work for recovery. This avoids writing content through outdated definitions; a matching local or deployed editor must be available to resume.
Options: Block save and publish until the editor matches / Allow draft saves; block only publication until it matches
Selected: Block save and publish until the editor matches
Notes: 
```
