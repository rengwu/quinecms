## Question 30

```text
Round: i18n: remaining choices
Question: What should happen to a language's stored copies when i18n is turned off or the language is removed?
Description (Markdown source):
The prototype keeps them (labelled **Assumption**). Two facts matter:

- A kept copy becomes eligible again as soon as its language comes back (DEC-200), even if the English changed in the meantime (no source-change tracking, DEC-201).
- Content is saved in Git, so deleted copies can be recovered from history.

Try: http://localhost:5317/?s=settings
Recommendation: Keep them when i18n is turned off; delete them when the language is removed. Turning off is usually temporary and Settings shows how many copies are kept. Removing is deliberate, and deleting stops hidden copies from coming back unnoticed.
Options: Keep them when i18n is turned off; delete them when the language is removed, after a confirmation with the count / Keep them in both cases / Delete them in both cases, after a confirmation with the count
Selected: Keep them when i18n is turned off; delete them when the language is removed, after a confirmation with the count
```

## Question 31

```text
Round: i18n: remaining choices
Question: What should happen when a language is added to a site that is already live, before anything is translated?
Description (Markdown source):
Settings publish with content (DEC-205), and Publish sends all pending edits together. So after adding Indonesian:

- **Fallback policy:** the next Publish creates every page under /id/, entirely in English until translated.
- **Strict policy:** Publish is blocked for every change until all items have complete Indonesian copies.

The Kahf pilot starts with both languages, so it doesn't hit this.
Recommendation: Accept it for the first release. It adds no new state. Add the switch later if a live site needs to prepare a language before launch.
Options: Accept it: translate under the fallback policy, switch to strict when done / Add a per-language “Visible to visitors” switch in Settings; hidden languages can be translated and previewed but aren't published or checked by strict
Selected: Accept it: translate under the fallback policy, switch to strict when done
```

## Question 32

```text
Round: i18n: remaining choices
Question: Can a list of rows (Key ingredients, FAQ items, a block's cards) have different rows in each language?
Description (Markdown source):
The prototype shares rows: you add, remove and reorder them in English, and translate each row's per-language fields. Page sections already work this way (DEC-196), and DEC-223 assumes it for new rows.

A list of references (for example related products) is a single value and follows its field setting either way.

Try: http://localhost:5317/?s=incomplete (Key ingredients)
Recommendation: Shared rows. One structure to maintain, and each translated row stays matched to its English row. Cost: a language can't add or drop rows; content that really differs goes in a per-language text field.
Options: No: rows are shared; only fields inside rows can be per language / Yes: a list can be set per language, giving each language its own rows
Selected: No: rows are shared; only fields inside rows can be per language
```

## Question 33

```text
Round: i18n: remaining choices
Question: Should search engines index fallback pages?
Description (Markdown source):
A fallback page such as /id/products/daily-gel-cleanser shows the English item inside the Indonesian layout (DEC-221), so it duplicates the English page.

The engine has no canonical links, sitemap or site address setting yet.

Try: http://localhost:5317/?s=missing
Recommendation: Mark them noindex. One tag, no new setting, and search results only list Indonesian pages that are actually in Indonesian. Visitors can still open them.
```

## Question 34

```text
Round: i18n: remaining choices
Question: Should visitors be sent to their browser's language automatically?
Description (Markdown source):
English stays at / and Indonesian at /id/ (DEC-198). The site is static, so a redirect would be a script on the page. Kahf's layout includes a language switch.
Recommendation: No automatic redirect. It needs no script, can't trap visitors or crawlers in the wrong language, and each URL always shows the same language.
Options: No: visitors choose with the layout's language switch / Redirect from / to /id/ on the first visit when the browser prefers Indonesian / Remember the visitor's last choice and redirect to it
```
