# GitLab compatibility verification

## Scope

[FEAT-publishing](../../features/publishing.md) and affected
[editor connection/recovery](../../features/editor.md), implementing DEC-135.
Selected checks cover GitHub regression safety, GitLab coherent reads and atomic
saves, races, lost responses, exact saved-snapshot publication, credential
destination binding and browser connection controls.

Aggregate: **Passed** for these local/mocked checks. GitLab server behavior,
permissions, protected branches, real approval/pipeline requirements and CORS have
not been verified against an account. No remote write or deployment occurred.

## Build and environment

macOS, Node v22.19.0, pnpm 10.34.1. Dirty tree based on
`348f1237f115541694f738bac77137333a4550d8`, including prior local-authoring and
concurrent admin-theme, heading and readable-usage changes. The
[source manifest](../../evidence/2026-10-08-gitlab/source-manifest.json) identifies
the application, generated code, scripts, tests, content, public assets and build
configuration. The implementing agent ran the checks; no independent review is
claimed.

## Limits and cleanup

GitLab is tested through a modeled API, with official API documentation/source
review, not a real server. The mock establishes client intent and failure handling;
it cannot establish exact live merge preparation timing, asynchronous branch
cleanup, CORS behavior or compatibility across self-managed versions. The adapter
requires fast-forward/no-required-squash project settings and the usual SHA-1
repository format. Human-review publication remains a separate potential workflow.

No token was entered in the browser. Only the owned local production-preview
tab/server were used and closed/stopped after the check. Original content and
unrelated browser tabs were preserved. Browser evidence covers a desktop connection
dialog; no mobile matrix or live provider integration is claimed.
