# Browser Back follows editor navigation

The requested [FEAT-editor](../../features/editor.md) behavior **passed**. The
aggregate run is **Failed** because the broader regression suite has one existing
local-authoring watcher failure, reproduced on the unchanged engine revision.

## Scope and implementation

The user's request makes browser Back perform the current view's Back action.
Navigation entries record depth only; draft content remains in React and tab
recovery. Existing Back/Cancel controls perform the actual transition. Hidden
parent forms cannot handle Back ahead of their visible child. Catalog previews
return to the library before closing it. UI Back and section changes remove
unneeded history steps. Forward does not reopen dismissed forms.

A single-entry prototype failed consecutive native Back presses in Chrome and
was replaced with entries created when entering each depth. The dev site was
restarted and its generated source checked before testing the replacement.

## Reproduction recipe

Run `pnpm exec vitest run tests/editor-navigation.test.ts` in the engine. For the
native check, generate an isolated site with `projectFixture()` through `tsx`,
then run the engine CLI's `dev --port 4338` from that site. Open `/` before
`/admin/` so the editor has a known preceding document. Unlock with the disposable
fixture login, open Home → text v1, edit Title, and press the actual browser Back
button twice. Confirm page then list, unchanged URL, and retained content.

Stop dev, run CLI `check`, `build`, `check-build`, and `preview --port 4338` from
the fixture. Repeat the edit and Back sequence in the production editor. The
third Back must show the native unsaved-change warning. Cancel it, discard only
the fixture edits in Settings, then verify Back leaves normally. JavaScript
`history.back()` tests alone do not establish native Chrome history behavior.
