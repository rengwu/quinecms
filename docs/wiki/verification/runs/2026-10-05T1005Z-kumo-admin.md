# Kumo admin refinement

## Scope

[FEAT-editor](../../features/editor.md) and the submission UI of [FEAT-publishing](../../features/publishing.md): replace admin controls with Cloudflare Kumo, remove status/recovery banners and the mode toggle, add mouse block sorting, and report submission validation through toasts. Implements DEC-048–DEC-050.

## Build and environment

Base commit `f6993528410bebeae1dafd70d52f57c1cc3e34d4`, with dirty implementation. The [source manifest](../../evidence/2026-10-05T1005Z-kumo-admin/source-manifest.json) covers the tested application, tests, configuration, fixtures, and lockfile, including new files. macOS, Node 22.19.0, pnpm 10.34.1. Safari was driven through native UI controls against the existing development server at port 4321 and an owned production preview at port 4322. No independent verifier.

Browser testing caught unreliable native HTML drag events in Safari; the final implementation uses pointer capture with a movement threshold and keyboard sorting. It also caught Toasty's initial portal effect resolving before the container ref was attached. The container now mounts first; a regression test asserts that submission toasts remain inside the styled dark portal.

## Limits and cleanup

Kumo form and portal tests use jsdom, with layout APIs stubbed; actual mouse movement, visibility, interaction and reload behavior were checked in Safari. Full cross-browser/touch coverage, password/Lock, real GitHub saves/publishing, R2 uploads, and hosting deployment were outside this UI run. Existing provider tests remain mocked.

Test-only content was restored in both origins, the owned test tab was closed, and preview PID 70790 was stopped. The user's existing development server remains running. No credentials, remote writes, commit, or deployment were involved.
