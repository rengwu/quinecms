# Kahf local recreation verification

The accepted local recreation passes its scoped build, content, browser and
editor checks. Thirteen logical pages render in English and Indonesian using
library designs and an independent site. This is evidence for the selected
sample, not a production deployment or a portable dependency release.

## Scope and build

Covers [FEAT-kahf](../../features/kahf.md),
[FEAT-internationalization](../../features/internationalization.md), the existing
editor/layout/collection boundaries and DEC-208–DEC-215/DEC-233. The implementation
and verification were performed by the same agent, not an independent reviewer.

- Engine: `7f7a47ba8409dc1bb9cdb44777869ca7c5930328`; application source unchanged
  during this phase. Engine wiki records are modified.
- Library: based on `47f22d1`, dirty with the Kahf layout, ten blocks, preset,
  local assets, tests and verification scripts. Tests use the sibling i18n engine.
- Independent site: `quinecms-site-kahf`, newly initialized local Git repository
  with no commit or remote. Site content matches the final explicit preset.
- Environment: macOS, Node 22.19.0, pnpm 10.34.1, Chrome through browser control.
  Dev at `http://127.0.0.1:4323`; built fixture at `http://localhost:4324`.
  Both use disposable site-owned credentials with no Git/R2 configuration.
- [Input/output manifest](../../evidence/2026-10-25-kahf/manifest.json) hashes the
  dirty library, independent site and actual emitted output, excluding credentials.

The library's development dependency and independent site's dependencies are
local links. The engine SHA's GitHub archive returned 404 during installation;
remote main was `207f3451776f7c3471ab89536a2aeee1f0edffe0`. The disposable artifact
fixture declares exact installed versions and symlinks the installed checkouts,
following the existing local test pattern. It does not establish a remote install
or satisfy the ordinary site's production dependency-pin requirement.

### Repairs made during verification

The first assembled check caught a JSX delimiter error. An initial editor test
used two React instances; the test aliases now use the installed engine's React
and renderer. These were repaired before the passing runs.

Visual checks exposed crowded translated navigation, mobile layouts that differed
from the source, and a hero text layer intercepting the video control. Navigation
now collapses at the appropriate container width; mobile compositions match the
source's image/text order; the video control is reachable and was retested.

The first audit found a second `h1` on Story. The hero now offers page/section
heading levels and the Paragon introduction uses a section heading. Editing and
cancelling also exposed redundant empty values in seeded language copies. The
starter was normalized through existing `pruneCopies`/`filesFor`; a test now
requires pages, entries and layout copies to remain canonical on unchanged edits.
No engine patch was needed.

Browser accessibility reads and one download wait timed out. The same browser's
documented DOM/screenshot controls resumed the checks. The backup export was not
used as evidence and no unrelated Downloads files were opened or changed. The
preview initially advertised IPv6 localhost, so `127.0.0.1:4324` refused the
connection; the advertised `localhost:4324` address worked. These were tooling
issues, not product failures. The final preview stop/status recipe uses the
engine's Astro executable because the fixture lacks a local `.bin/astro`.

The wiki build/check passes. The report metadata checker accepts this run but
[flags nine older reports](../../evidence/2026-10-25-kahf/report-metadata.json) whose historical result labels are not exactly Passed,
Failed or Untested. Those pre-existing records were left unchanged; this is
documentation metadata drift, separate from the product results above.

## Measurements and limits

The retained public HTML was approximately 139–362 KB raw, with median compressed
HTML around 24 KB. The emitted JavaScript graph is about 88 KB gzip per page and
uses shared modules. These values exclude media transfer, browser cache effects
and live provider traffic. Local Kahf assets total about 32 MB, mostly three
source videos; they are shared across routes. The build log records actual timing
and module sizes. These measurements do not establish full-corpus scale.

Source content and intentional simplifications are recorded in the library's
`presets/kahf/v1/README.md` and asset `sources.json`. The sample omits service flows,
peripheral destinations, category archives and placeholder content. The static
blog feature and product cards replace decorative carousels. Search is a compact
title search over retained entries/pages; footer/navigation are reduced to scope.
English bridge prose is an editorial translation; the mosque prose retains its
original Indonesian. This is a manual fidelity review, not a pixel-difference
certification or approval by the reference site's owner.

Outside the selected local acceptance: clean remote pinned installation, live
GitHub/GitLab writes, R2 uploads, hosting rebuilds/deployment, native-device and
cross-browser performance, and assistive-technology testing. Save/Publish provider
transport and preview islands are mocked in the two editor-control tests; separate
browser checks establish actual preview rendering. No live provider is claimed.

Raw URL fields and Markdown are intentionally literal under the current engine
contract. A link inside a fallback English item can return to English; collection
links and the language switch resolve language routes. A first-class internal-link
picker and page SEO/sitemap work remain possible later improvements, not required
engine additions established by this sample.

No commit was pushed and no site was deployed. Test-only browser edits were
discarded; source content stayed equal to the preset. The disposable built preview
was stopped, while the independent dev site is left running on port 4323.
